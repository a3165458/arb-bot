## 快速开始

```bash
cargo build --release

# 资金费套利榜（默认）
./target/release/arb-scan
./target/release/arb-scan BTC ETH SOL
./target/release/arb-scan --json | jq '.totals'

# 跨所价差套利榜
./target/release/arb-scan --view spread

# 改口径
./target/release/arb-scan --fee 0.0002 --amortize-days 14 --spread-hold-days 1
./target/release/arb-scan --max-entry-basis-pct off   # 关掉基差门槛

# 实测收敛时间：对价差榜前 N 条候选拉两腿 K 线，拟合基差半衰期
./target/release/arb-scan --view spread --measure-convergence 30

# 强平距离与保证金年化按 5 倍逐仓算（不影响排名）
./target/release/arb-scan --leverage 5

# 看板（默认只监听 127.0.0.1:8080）
./target/release/arb-web

# 纸面交易：扫描 → 深度体检 → 闸门 → 双腿执行 → 对账（不碰真实资金）
./target/release/arb-paper BTC --size 1000
./target/release/arb-paper --view spread --size 2000 --top 3

# 带任务规则开仓：费差年化跌破 5% 平仓、强平距离不足 10% 减仓、两腿数量偏差超过 1% 平仓
./target/release/arb-paper BTC --size 1000 --leverage 5 \
  --min-funding-apr 5 --liq-protection 10 --size-mismatch 1

# 指定两条腿的场所（看板「策略」页生成的命令就是这个形状）
./target/release/arb-paper TSLA --long lighter --short hyperliquid-xyz --size 1000 --leverage 3

# 持仓监控：不开新仓，按台账里每笔仓位的规则评估并执行（--once 只跑一轮）
./target/release/arb-paper --watch

# 实盘（Hyperliquid × Lighter）：默认只读，只连接、对账、出计划，不签名、不发单
./target/release/arb-live status
./target/release/arb-live open ETH --long hyperliquid --short lighter \
  --size 500 --leverage 3 --daily-pnl 0
# 真实下单：必须同时给 --enable-trading 与 --market-slippage
./target/release/arb-live --enable-trading --market-slippage 0.003 open ETH ...
```

| --- | --- |
| 机会 | 全市场两两配对的资金费榜与价差榜（原有功能），附强平距离与保证金年化 |
| 策略 | 选两家场所 → 同时上市的合约与两边费率（APR / 8h / 1h）→ 选中一对腿，右侧给出开仓计划、可复制的 `arb-paper` 命令，以及「下单」区（预览 → 纸面 / 实盘开仓） |

## 架构

```
crates/
  core/      领域类型、错误、配置、十进制工具、多档盘口与吃单估算。不做 IO、不排名。
  venues/    14 家场所的公共行情连接器。批量 fetch_all()，外加按需的逐合约深度与 K 线。
  scanner/   归一化 → 身份分簇 → 可信度筛查 → 摊销排名；价差榜可实测基差半衰期；
             杠杆与强平模型（强平价、强平距离、健康度、减仓比例、保证金年化）。
  exec/      执行层：闸门、双腿下单与回滚、等比例减仓、持仓规则监控、对账、追加式台账；
             纸面券商 + Hyperliquid / Lighter 真实券商。
  web/       axum 服务 + 内嵌单页看板。与 CLI 共用同一份 scanner 计算。
```

CLI 与看板**必须**是同一份排名逻辑。看板不自己算净年化，只把参数交给服务端重排名
（`arb_scanner::rerank`）—— 前端复算一遍等于在两处各写一份口径，迟早漂开。

## 成本模型

一次往返只有四类现金流，别的一律不算：

```text
资金费（按天累积）   +  daily_spread × N
手续费（一次性）     −  round_trip_fee
穿价（一次性）       −  round_trip_spread
基差（一次性）       +  (b_entry − b_exit) × notional
```

**整轮排名只用一档穿价。** 多档滑点要逐合约拉深度，不能对近千个合约各打一次。
`arb-paper` 只对准备下单的那几条候选拉深度，按盘口逐档吃单估算滑点；
吃穿全部档位时成交名义小于目标，闸门会拒绝，而不是把滑点当成 0。

### 手续费与穿价

手续费两腿各开平一次（共 4 笔）。**穿价**是市价买要吃 `ask`、市价卖只能拿 `bid`：
一次往返四条腿的净额是 `−(spread_short + spread_long)`，其中 `spread = (ask − bid) / mid`。

两者都是**一次性**成本，摊到持有期上。把一次性成本整额扣在**一天**的价差上，等于
假设只持有 1 天 —— 那会同时做错两件事：筛掉真实可盈利的机会，并鼓励高换手。
`ARB_AMORTIZE_DAYS`（资金费视角，默认 7）与 `ARB_SPREAD_HOLD_DAYS`（价差视角，
默认 3）就是各自的「打算持有多少天」。

单腿费率**优先用交易所公开接口报的真实值**，拿不到才回落到 `ARB_FEE_PER_SIDE`。
「报了 0」与「没报」严格区分（Lighter 的吃单费率真值就是 0）。

**拿不到盘口时穿价是 `None`，不是 0。** 报告里 `spread_unknown` 会标出来：那时成本是
**下界**、净收益是**上界**。CLI 与看板都会显式提示有多少条属于这种情况。
实测 85% 的读数有盘口（Hyperliquid 系 / Lighter 系 / Variational 的批量接口不提供盘口，
详见场所矩阵）。只想看成本可测的机会，用 `ARB_VENUES` 排除这六家即可。

### 基差：两条策略各自的假设

基差项是 `b_entry − b_exit`，而 `b_exit` 在进场时**未知**。把它当 0（也就是把
`b_entry` 当成确定成本）是错的：基差保持不变时，这笔钱根本不会发生。

所以不猜，而是两条策略各给一个明确的假设：

| 视角 | 假设 | 一次性基差项 | 净年化公式 |
| --- | --- | --- | --- |
| 资金费套利 | 基差保持不变 | 0 | `(日化费差 − 成本 ÷ N_f) × 365` |
| 跨所价差套利 | 可成交价差收敛到 0 | `+b_executable` | `b_executable − 平仓穿价 − 手续费`（一次性，不折年） |

价差视角用的是**可成交价差** `(空腿买一 − 多腿卖一) / 中间价`，不是两家标记价的差。
标记价碰不到；盘口一宽，标记价差为正、实际开仓为负是常态。任一条腿没有对应档位
（Variational 的 RFQ、Lighter / Hyperliquid 的批量行情）时，这笔价差不存在，不进价差榜。
开仓穿价已经含在买一/卖一里，年化时只再扣平仓那一次穿价和全程手续费。

**价差视角不把持有期内的资金费算进净收益**（那部分在「毛年化」列）。理由：两条榜
必须真的不同 —— 把 carry 算进去，价差榜会被高资金费的配对占满，与资金费榜几乎重合。

**基差扩大是无界风险**，对资金费视角而言它不是「一个情景」而是敞口：`b_exit` 往不利
方向走多少就亏多少。所以它靠**进场门槛**挡：`ARB_MAX_ENTRY_BASIS_PCT`（默认 `0.5`，
即不利基差不超过 −0.5%）。负的入场基差意味着你要靠基差**反向扩大**才赚得回来，
那是在赌均值回归不会发生。价差视角只收正基差的方向，不受这个门槛影响。

实测（11 家场所 / 6464 条机会）入场基差中位数 +0.013%、p10 −0.224%。门槛取 0.5%
只挡掉 3.2% 的机会，但挡掉了净年化 Top100 的 15%；取 0.1% 会砍掉 Top100 的 54%
—— 那是在砍噪声，不是砍风险。

被挡下的配对会逐条列在 CLI 与看板上，不是静默丢弃；`off` 可以关闭门槛。

一个真实的例子（同一时刻，ONE/USDT）：

| 门槛 | 榜首配对 | 净年化 | 入场基差 | 收敛情景净年化 |
| --- | --- | --- | --- | --- |
| 开（0.5%） | bitget → mexc | +14.4% | +0.117% | +20.5% |
| 关 | bitget → gate | **+124.9%** | **−4.109%** | **−89.4%** |

关掉门槛时排到榜首的那一条，基差一收敛就是每年亏 89% —— 只看「净年化」是看不出来的。

Hyperliquid 的 `metaAndAssetCtxs` 里有 `impactPxs`，但那是**冲击成交均价**（吃固定名义额
后的均价），不是最优买卖价 —— 拿它当一档价会把穿价成本算错。逐币的 `l2Book` 能拿到
真实盘口，代价是每个合约一次请求（近 200 次），所以本轮保持 `None`。

**结算周期必须逐合约读。** 逐合约端点普遍不返回周期，只能回落到 8h；而 4h 合约被
当成 8h 会让日化低估一半（1h 低估 8 倍），排名照常算得出来，看不出来。所以连接器
契约只给批量端点。

**新增的三家都是「同一套 API 的另一个实例」**，各有独立的清算所与保证金，所以记为
独立场所：

- `hyperliquid-xyz` / `hyperliquid-io` 是 Hyperliquid 的 HIP-3 子交易所（美股、指数、商品、
  外汇、Pre-IPO）。请求体带 `"dex"`，币名带前缀（`xyz:TSLA`），对外的合约名去掉前缀；
  深度与 K 线查询时再按本 dex 的 `meta` 还原成带前缀的原名。
- `lighter-rh` 是 Lighter 在 Robinhood Chain 上的部署（`api.rh.lighter.xyz`，USDG 保证金）。
  资金费表与主网同口径（8 小时基准、混着别家的对照行）。它的限频比主网紧，连续请求会回
  `code=23000`，那一轮如实报为取数失败，下一轮自动恢复。

**Arcus**（`api.arcus.xyz`）是 Robinhood Chain 上的订单簿永续 DEX，USDG 保证金，加密与美股、
商品、指数永续各半。几个口径：

- 每期费率取 `nextFundingRate`（下一次结算的预测），不是 `fundingRate`（上一次已结算的）。
- 标记价 `"0"` 表示还没有，官方明确不许回落到预言机价；预言机价填指数价。
- 股票类市场盘后（`isOutsideRth`）初始保证金率换成更高的 `offHoursInitialMarginFraction`，
  最高杠杆与强平距离按当前生效的那个算；盘后状态未知时按更严的算。
- 股票类市场有美元持仓上限 `openInterestCapNotional`，持仓名义触顶时标「OI 上限」。
- Arcus 的 `QNT`、`BE`、`BOT` 是**股票**，别处同名的可能是加密币，靠价格分簇拆开，不在连接器里改名。
- 永续目前是白名单内测：扫描不受影响，实盘需要地址在白名单里。

少数合约在别家用的是另一个名字，**按同一分钟的价格核实过**才做映射：`xyz:GOLD → XAU`、
`xyz:SILVER → XAG`、`io:ANTH → ANTHROPIC`、`io:OAI → OPENAI`。名字不同的不凭印象映射：
`xyz:CL`（原油期货，89.75）和 `USO`（原油 ETF，144.23）、`xyz:SP500`（7766）和 `SPY`（773.71）
都是不同资产。

几处已经踩过的坑（都写在对应模块的文档里）：

- **Lighter 的 `/funding-rates` 是「8 小时基准」的横向对照表**，同一张表里还混着
  binance / bybit / hyperliquid 的费率。直接当每期费率会让它的日化虚高 8 倍并霸榜。
- **Variational 的 `funding_rate` 是年化**，不是每期费率；不换算会让每一行虚高约 1000 倍。
- **Gate 的 `tickers.total_size` 是双边持仓**，用它算 OI 会翻倍。
- **MEXC 的吃单费率逐合约不同**（实测 0 / 0.0001 / 0.0002 / 0.0004 / 0.001），
  用全局默认值会让一部分合约的成本算错。

## 数据可信度

可疑读数**标记但不隐藏**：照常展示（带原因），只是不参与配对。静默丢掉比标出来更危险
—— 用户会以为自己看到的是全部数据。

- 跨场所离群：同一合约内与中位数的偏离超过 `max(8σ, 0.5%/天)`。
- 身份无法核实：缺参考价、无法确认与其它场所是同一资产。
- 场所取数失败：`/api/scan` 的 `venues[].ok=false` 与失败原因，面板顶部会明确列出。

**这个判据发现不了什么**：单次快照无法区分「场所偶发返回 0」与「该合约费率确实接近 0」。
要抓前者需要跨轮次的一致性检查，属于后续 `--watch` 模式的工作。这里不假装能做到。

## 杠杆与强平

双腿对冲掉的是价格方向，对冲不掉的是**保证金**：价格单边走 20%，一条腿赚、一条腿亏，
合起来是零 —— 但亏的那条腿在自己的场所里被强平，赚的那条腿就成了裸敞口。所以杠杆决定的
不只是收益率，更是「价格能走多远，这笔对冲还在」。

强平价按 Hyperliquid 官方的逐仓公式算（`l` 为维持保证金率），开仓时只和杠杆 `L` 有关：

```text
多：强平距离 = 1 − (1 − 1/L) / (1 − l)
空：强平距离 = (1 + 1/L) / (1 + l) − 1
```

只用 `1/L` 会把强平价算远：5 倍、维持保证金 1% 时空腿是 18.8%，不是 20%。扫描榜只展示逐仓模型；
全仓账户风险不能由这套公式推断，交易计划选全仓后不显示模型强平距离。

| 字段 | 含义 |
| --- | --- |
| 强平距离 | 两腿里更近的那个。任一腿算不出来就是「未知」—— 只看算得出的那条会把风险看轻 |
| 健康度 | ≥ 20% 健康、≥ 8% 注意、更近危险 |
| 保证金年化 | 资金费年化 × 名义 ÷ 两腿保证金合计；两腿同为 L 倍即 `资金费年化 × L / 2`。假设基差不变、不被强平、没有借贷成本 |
| OI 上限 | 至少一条腿的场所报告该合约已触及持仓量上限：只能减仓，开不了新仓。照常排名、不藏起来 |

**只有 Hyperliquid（含 HIP-3）与 Lighter（含 RH）的批量接口公开最大杠杆与维持保证金率**：
Hyperliquid 是 `maxLeverage`，维持保证金率按官方规则取 `1 / (2 × maxLeverage)`；Lighter 是
`min_initial_margin_fraction` / `maintenance_margin_fraction`（万分之一，`default_initial_margin_fraction`
只是新账户默认值，不是上限）。其它场所显示未知，不拿典型值顶上。两者都只描述最低风险档，
大仓位落到更高档时强平会更近。持仓量上限只有 Hyperliquid 公开（`perpsAtOpenInterestCap`）。

杠杆（`ARB_LEVERAGE`，默认 3）**不影响排名**，只影响风险列。默认 3 倍是按常见维持保证金率
（1%）仍落在健康档的最高整数杠杆：3 倍约 32%，5 倍约 19%。

## 实测收敛时间

价差净收益是一次性的，不按持有天数折年。`--measure-convergence N` 会
跳过没有公开 K 线的场所，对净价差最高的前 N 条候选拟合基差半衰期，
标在净收益旁边，说明衰减有多快，**不改变这一笔的金额**：

```text
Δb_t = α + β · b_{t-1} + ε        半衰期 = −ln2 / ln(1+β) × 采样间隔
```

半衰期只写回被拟合的那一对腿。同一合约在别的场所之间是另一个基差过程，不能共用这个数。

拒绝给答案的三种情况（返回 `None`，排名回落到配置值并标记 `hold_measured = false`）：

- 样本不足（< 30 根）；
- `β ≥ 0`：基差在发散或随机游走，「收敛时间」这个概念不成立；
- `R² < 0.02`：上一刻的基差几乎解释不了下一刻的变化，由 β 推出来的半衰期只是噪声。

把一次性价差 ÷ 半衰期 × 365 会把「几小时收敛一半」说成一年重复几千次，那个年化不是收益。
榜上的价差净收益就是这一笔：可成交价差减去平仓穿价和手续费。

实测样本（11 家场所 / 前 30 条候选）：OPENAI/USDT 半衰期 0.10 天（R²=0.13）、
ONE/USDT 0.45 天（R²=0.03）、ANTHROPIC/USDT 0.56 天（R²=0.02）。
当时 11 家里 9 家实现了 K 线；Lighter 与 Variational 没有公开的逐合约 K 线端点。
新增的 HIP-3 子交易所复用 Hyperliquid 的 K 线实现（带前缀查询），Lighter-RH 同 Lighter 没有。

## 执行层

`arb-paper` 与 `arb-live` 把「扫描出来的机会」变成「可审计的下单计划与仓位记录」，两者共用
同一份扫描、闸门、执行器与规则评估（`arb_exec::cli`），只是券商不同。

| 组件 | 做什么 |
| --- | --- |
| `preflight` | 下单前的闸门：名义额上限、仓位数量、当日亏损、滑点、入场基差、限价以内的深度、持仓量上限、开仓强平距离（危险档拒绝，未知放行并打印）。每一条拒绝都说清是哪一条拦的。 |
| `executor` | 双腿执行 + **失败回滚** + 两腿等比例减仓。交易所没有原子双腿，所以回滚是必需品。 |
| `monitor` | 持仓期间的任务规则：费差自动平仓、爆仓保护减仓、数量失衡平仓。只评估、不下单，动作交给执行器。 |
| `reconcile` | 断线/重启后把本地台账与券商状态对齐，列出每一处不一致。 |
| `ledger` | 追加式 JSONL 台账。事故总是发生在状态转移的缝里，覆盖式存储会把缝抹掉。 |

**双腿原子性**没有银弹，这里四条一起做：

1. **难成交的腿先做**（按估算滑点排序）。它失败时你手上什么都没有。
2. **第二腿按第一腿的实际成交数量下单**，而不是按同一名义额：两腿对冲的是数量。
   第一腿部分成交、或第二腿数量偏差超过 0.5% 时，回滚已成交的腿。
3. **失败就回滚**已成交的那条腿，并把仓位标成 `Unwound` 而不是「开仓失败」——
   后者会让人以为什么都没发生。
4. **超时/断线靠对账**发现本地不知道的成交。对账按**标的数量**核对每个合约的净持仓，
   台账之外的持仓或挂单都算不一致，必须人工介入。

**开仓执行报告**（`report` 模块）：每笔成功的开仓都把「下单前的计划」和「实际成交」对成一份报告，
随仓位一起落盘（`PairPosition.open_report`），日志、Telegram 开仓通知、看板结果面板与持仓卡片
都用同一份：每条腿的下单时最优价、预估均价（按这笔名义吃盘口算出的）、实际均价、各自的不利偏差
（买腿高于参考价、卖腿低于参考价为正），锁定价差（最优价 / 预估 / 实际三个口径），两腿合计比预估多花
多少 USDT，开仓手续费，以及耗时：报价到成交、两腿间隔（只有一条腿的窗口）、执行器合计。
下单点「确认」时服务端会**重新**现扫、拉盘口、算计划，它和你之前看的预览不是同一份，所以这份报告是
唯一能对上「实际执行的是哪份报价」的记录。盘口第一档很薄、后面隔得远（2026-10-01 PONS：Lighter
卖一只挂了 $52，2800 的买单吃穿好几档、比卖一差 0.10%）时，吃穿的几档已经算在预估均价里，
报告里「比预估」小、「比最优价」大就是这种情形；两腿一起漂移时锁定价差几乎不变。

**下单速度**：双腿之间永远有一个只有一条腿的窗口，所以链路上凡是不影响安全的往返都压掉了：
开仓前两条腿的券商**并发预热**（`Broker::prepare_open_mode`：核对所选保证金模式与杠杆、刷新市场元数据）——第二腿的杠杆
设不上，在第一腿成交之前就发现，不必先成交一条再回滚；核对过的杠杆短时间内（20 秒）`place` 不再
重复核对；Arcus 的市场列表 20 秒内复用（下单前后各读一次）；Lighter 下单前「订单号是否已被占用」
与市场列表并发读；下单后轮询订单从 250ms 改为前 10 次 100ms；Arcus 成交明细 300ms 轮询（原 1 秒）。
对账各场所并发、两个盘口并发拉、两个账户的可用保证金并发查，且保证金核对与盘口/计划并发进行。
**没动**的安全栏：nonce 预留、订单意图日志、幂等 `client_order_id`、「订单号已被占用」检查。
看板开仓与预览的响应里带 `phases_ms`（对账、现扫、盘口与保证金、下单各花多久），日志里有
「开仓各阶段耗时」。

每个订单的意图**先落盘再发单**。场所接单不等于成交：执行器总是回查订单状态，
仍在簿上的撤掉再查，成交多少就记多少。查不到结果时停止执行，不当作拒单。

下单用**幂等**的 `client_order_id`：开仓 `{仓位}-{腿}-{尝试次数}`，减仓 `{仓位}-{腿}-trim{n}`，
退出（平仓 / 回滚）`{仓位}-{腿}-exit{n}`。同一次尝试复用同一个 id，由交易所侧去重；
退出每次重试换号，完全成交的腿从仓位上移除，部分成交按实际数量缩小，
重试只平剩下的数量。超时重发而不复用 id 是这类系统最常见的事故来源。

### 保证金模式（全仓 / 逐仓）

看板策略表单可选「逐仓」或「全仓」，选择保存在同一浏览器；CLI `arb-live open` / `arb-paper`
使用 `--margin-mode isolated|cross`。默认逐仓，旧订单与旧台账继续按逐仓读取。两条腿使用同一所选模式，
计划、预览、开仓、订单日志和持仓台账都保留模式，平仓 / 回滚 / 减仓沿用原模式。

- **全仓接入**：Binance、Aster、Bitget、Bybit、Gate、MEXC、OKX、Arcus、Hyperliquid 主站、Lighter、Lighter-RH。
  合约和账户仍须支持；开仓前配置并读回确认，不支持或读回不符就拒绝，不会悄悄降为逐仓。
- **限制**：Hyperliquid `xyz` / `io` 暂只提供逐仓；主站的 `onlyIsolated` / `noCross` / `strictIsolated`
  合约拒绝全仓。Ourbit、Variational 只有行情接入，不能通过机器人下单。Bybit UTA 的全仓要求账户已处于
  `REGULAR_MARGIN`，逐仓要求 `ISOLATED_MARGIN`；机器人不切账户级模式，不支持组合保证金模式。
- **不改现有持仓**：同合约已有非零持仓时拒绝开新仓及改杠杆 / 模式；模式不是持仓规则，不能在规则编辑器中切换。
  监控发现交易所报告的模式与台账不符，会暂停该笔自动规则并提示核对，不替用户转换。
- **全仓风险口径**：名义额 ÷ 杠杆只是预计初始占用，不是这条腿独立的保证金。计划不推算全仓强平价；
  持仓保护只信交易所报告的有效强平价，触发时整笔退出，不用逐仓比例减仓公式。未知时提示无法评估，
  不保证关闭本笔能恢复整个账户安全。Arcus 没有接入有效强平价；MEXC 文档的 `liquidatePrice` 只说明逐仓口径，
  这两家的全仓爆仓保护无法依靠当前接口执行。推荐专用账户、保守杠杆，并在交易所监控账户风险。
- **自动追加保证金仅逐仓**：全仓开仓 / 保存规则必须明确关闭该规则；不会自动给共享账户补款。

这些适配经过离线回归测试，**没有用真实账户逐家下单验收**；首次实盘请先以最小金额验证账户及合约限制。

### 持仓规则

开仓时用 `--min-funding-apr` / `--liq-protection` / `--size-mismatch` / `--basis-exit` /
`--take-profit` / `--auto-margin` + `--auto-margin-max` 设定，连同保证金模式、杠杆与逐仓保证金（全仓不填）一起写进台账；
`arb-paper --watch` 与看板后台共用规则执行流程，每轮重放台账、只拉持仓涉及的场所，逐笔评估：

| 规则 | 触发 | 动作 |
| --- | --- | --- |
| 数量失衡 | 两腿标的数量偏差 > 门槛（0.5% ~ 100%） | 整笔平仓 |
| 基差收敛平仓 | 当前**标记价**基差（空腿 − 多腿）≤ 目标（价差套利的退出条件，±5% 以内）**触发**；再现拉两边盘口、按持仓数量算「现在平掉整笔」的预估盈亏（含已付与将付手续费），**为正才平** | 整笔平仓 |
| 含资金费止盈 | 标记价估算的净盈利 ≥ 正数目标（USDT）**触发**；再按两边盘口、平仓手续费与穿价核对，含结算资金费的净额仍 ≥ 目标才平 | 整笔平仓 |
| 费差自动平仓 | 最近 6 小时**平均**毛费差年化 < 门槛（开仓成本已付，是否继续只看往后；拉不到历史时退回当前读数） | 整笔平仓 |
| 自动追加逐仓保证金 | 任一腿强平距离 < 触发线；必须同时配置累计上限（USDT），触发线高于爆仓保护门槛 | 优先给最危险的一腿补款，目标距离为触发线的 1.5 倍；补不了时回退到已配置的爆仓保护 |
| 爆仓保护 | 任一腿强平距离 < 门槛 | 两腿等比例减仓，把距离拉回门槛的 1.5 倍 |

同时触发时只执行优先级最高的一条（按表格顺序）。基差收敛目标不低于开仓时的标记价基差时直接拒绝开仓
（开仓就会触发）；收敛到目标就平只赚得到入场与目标之间那一段，所以还要求「吃完深度后的价差 − 目标 −
平仓穿价 − 往返手续费」为正，否则拒绝并给出保本目标。目标与入场基差同一个口径（标记价）；但标记价不在
买卖盘中间（Arcus 的标记价目前等于预言机价），2026-09-30 实盘 NEAR 就是标记价基差收敛到 0.09%、按盘口平仓
的价差却是 0.196%，按标记价平掉亏了 1.29 USDT —— 所以标记价只负责触发，平不平按盘口核对；盘口拉不到或
深度不够这笔数量时继续持有并写明原因，绝不退回按标记价平仓。平仓备注按实际成交记已实现盈亏（含全部手续费、
不含资金费）和开、平仓两次的成交价差。爆仓保护门槛不低于开仓强平距离时直接拒绝
开仓 —— 那会让新仓第一轮就被砍掉一截；任一腿不公开维持保证金率时，这条规则无从执行，也拒绝。

**止盈口径**：剩余持仓价格盈亏 + 已实现的部分退出盈亏 + 本仓位已结算资金费 − 已付手续费；
盘口确认另计平仓手续费与穿价。实盘止盈决策与启用止盈的规则修改确认都现查结算流水，不用页面的 5 分钟缓存；
资金费查询失败或场所未接入时跳过止盈并说明原因，旧的成功缓存也不能授权平仓，不能拿 0 代替未知。

启用止盈的仓位，后台每轮都会按两边盘口（各 20 档、按整笔数量逐档吃单）估算「现在平掉整笔能拿多少」，
持仓页在「止盈进度（标记价）」旁显示「按盘口现在平仓可得」；实际是否止盈以后者为准。
标记价已达标、但盘口核对不达标或盘口不可用时，日志记一条 WARN「止盈按标记价达标，但盘口核对未通过」，
并推送 Telegram 提醒（同一笔仓位 30 分钟内最多一条）。
纸面资金费明确为 0。持仓卡、规则评估与 Telegram 共用服务端净额，浏览器不复算策略盈亏。

**补保证金边界**：

- 实盘实现覆盖 Lighter、Lighter-RH、Hyperliquid（含 `xyz` / `io` HIP-3）与 Arcus，**仅逐仓**；两腿都必须具备能力，
  否则预检与开仓拒绝。跨仓不在本功能范围。补的是该场所账户里已有的可用保证金，不跨场所转账。
- 一轮只补最危险的一腿；按剩余累计额度夹住金额，最少 1 USDT，最多使用该场所可用资金的 90%；
  成功或结果未知后冷却 90 秒，失败带退避。累计额度属于整笔仓位，不因规则修改或进程重启重置。
- 累计金额在发送前写台账。明确拒绝 / 发送前错误退回额度；结果未知保留额度，不重发原请求。
  单次请求禁止自动重定向重放；回读确认会核对保证金和持仓身份，不能把平仓重开的读数当成补款成功。
- 看板规则轮执行动作后，让相关合约的保证金状态缓存失效，包括补款结果未知或动作可能部分执行的错误；
  缓存回写与失效互斥，在途旧读数不能在规则轮清缓存后重新写回来。
- 上限耗尽、可用资金不足、补款失败等情况会说明原因；若爆仓保护也已触发，回退到减仓，否则记录需要关注的状态。
  CLI、看板与 Telegram 会显示补款动作、累计已用 / 上限及异常。
- 券商写入路径已通过本地协议夹具与回读回归测试，**未进行真实补款验证**。协议依据与离线验签不能冒充服务器已接受请求：
  - **Lighter-RH**：[官方 RH 文档](https://apidocs.lighter.xyz/docs/lighter-rh)明确说明使用与主网相同的交易格式 / 签名库，抵押资产为 6 位小数的 USDG；
    [固定版本 Python SDK](https://github.com/elliottech/lighter-python/blob/ebc50660efc99f31e4055418e4514255456cb060/lighter/signer_client.py#L1351-L1354) 的 `update_margin` 使用 `1e6` 缩放。
    已用钉住 SHA-256 的原生签名库与独立编译的官方 Go 源码核对实际交易哈希 / Schnorr 签名：正确链通过，换链或篡改金额 / 账户失败。
    ABI 字段仍名为 `USDCAmount`，不表示把 USDG 兑换成 USDT。
  - **Arcus**：[官方认证说明](https://docs.arcus.xyz/api-reference/authentication.md)与[官方发布的 REST 客户端](https://app.arcus.xyz/assets/index-BcyibAMy.js)共同确认
    `纳秒时间戳 + adjustIsolatedMargin + 规范 JSON(body)` 的旧式签名；独立 Node/OpenSSL 验签与 Rust 向量一致。
    HTTP `422` 只有 `status=REJECTED` 且带拒绝原因才算明确拒绝；`ACK` / `APPLIED` 等矛盾状态或缺状态保留为结果未知，不退回已预留额度。

例如纸面开仓加上 `--take-profit 20 --auto-margin 15 --auto-margin-max 100 --liq-protection 8`：
净盈利达到 20 USDT 时先核对盘口；强平距离低于 15% 时尝试补到 22.5%，整笔仓位累计最多补 100 USDT。
开仓时触发线不低于任一腿当前强平距离会被拒绝，缺维持保证金率也不能配置补款或减仓规则。

减仓比例有解析解。假设这条腿的权益留在逐仓保证金里（减掉部分的已实现盈亏计入保证金）：

```text
f = i·(t − e) / (i·t + 100·l)，i = 1 − l（多）或 1 + l（空），e/t 为当前/目标强平距离（%）
```

执行器按同一假设回写仓位（名义按实际成交数量缩小，保证金加上已实现盈亏、扣掉手续费），
单测验证过「按 f 减仓后重算的强平距离正好等于目标」。两边假设不一致时，价格偏离入场价越远，
减完的距离离目标越远 —— 在入场价上测不出来。

旧台账没有杠杆与保证金字段，照常重放；它们的强平距离显示未知，爆仓保护跳过并打印原因。

## 实盘执行（`arb-live`）

连接的场所由 `ARB_LIVE_VENUES`（或 `--venues`，逗号分隔）指定，只连接列出的场所；每家的凭据见「环境变量」。
留空或写 `auto` 时**按凭据自动识别**：凭据填齐、格式也对的每一家都连上（至少两家）。
Hyperliquid 的钥匙齐全时，主站与 HIP-3 的 `hyperliquid-xyz` / `hyperliquid-io` 一起连上（共用钥匙，
但各 dex 的保证金互相独立：要在哪个 dex 开仓，就得在哪个 dex 有保证金）。
自动识别只看变量填没填、格式对不对，不联网；凭据填了但连不上时 `arb-live` 照样启动失败，不会悄悄少连一家。

**看板（`arb-web`）的实盘连不上时不阻塞启动**：配置错误（滑点、场所名、凭据格式、令牌）仍然启动即报错退出；
但交易所**暂时**连不上（维护、限频、网关 404/5xx）时，看板先启动 —— 行情、机会榜、价差监控、纸面、Telegram 照常 ——
实盘下单、持仓规则与对账暂停，后台每 60 秒重连。实盘连接仍是**全有或全无**：不会带着缺一家的半个实盘运行
（缺一家时对账会把那家的腿当成不存在，规则会作用在错误的数量上）。断开期间：实盘接口返回 `503` 并说明原因；
页面顶部显示红色横幅、徽章为 `live·down`；`/healthz` 返回 503（`live.disconnected=true`）；`/metrics` 的
`arb_live_connected` 为 0；Telegram 启动时推送一次、之后每 30 分钟提醒一次，连上时再推送一次；`/status` 也会显示。

| 子命令 | 做什么 | 需要下单权限 |
| --- | --- | --- |
| `status` | 各家账户的真实持仓、账户费率，与实盘台账逐合约对账 | 否 |
| `open` | 扫描 → 规则与强平校验 → 深度体检 → 闸门 → 双腿执行 → 再对账 | 不带时只出计划 |
| `close <仓位>` | 平仓；也用于重试停在 `Closing` / `Unwinding` 的仓位 | 是 |
| `watch [--once]` | 按规则监控并执行；自动重试没走完的退出 | 是 |

安全边界：

- **默认只读。** 不给 `--enable-trading` 时所有券商拒绝一切写操作（下单、撤单、改杠杆），
  任何路径都不签名写请求。构造券商时只做只读的认证检查。
- **开启下单必须给 `--market-slippage`**（小数，上限 0.05）。平仓、回滚、减仓没有限价，
  券商按发单前刚拉的盘口给出价格上限：买 ≤ 卖一 ×(1+s)、卖 ≥ 买一 ×(1−s)。所有订单都是
  限价 IOC，没有无上限的市价单。
- **开仓前对账必须干净**，`watch` 每轮对账不干净就跳过自动动作。请用**专用账户**：
  台账之外的任何持仓都会拦下开仓；台账里有仓位落在没连接的场所上时同样拦下。
- **当日已实现盈亏由操作者给出**（`--daily-pnl`，必填）。各家的历史接口都有条数上限，
  这里不把「查不全」当成 0。
- **杠杆必须是整数**，且不超过两腿共同上限（超过直接拒绝，不偷偷降档）。券商在开仓单之前
  把该合约设为所选保证金模式并回读确认；**账户级设置一律不改**，不兼容时拒绝并说明要改什么。
- **独立文件**：实盘台账 `arb-live-ledger.jsonl`，每家一份订单意图日志
  `<--journal-dir>/arb-live-<场所>-orders.jsonl`（独占锁，权限 0600）。意图先 fsync 再发单；
  出现无法核实的订单时**不要删日志重试**：券商会拒绝重发任何已记录的订单号，先对账。
  一个账户 / API key 只跑一个进程。
- **交易所明确拒单**（订单不存在、业务错误码）记为 `Rejected`；**结果未知**（超时、5xx、
  文档标明「执行状态未知」的错误码）保留意图、返回错误，由对账决定。

各家要求与签名核验情况：

**不支持实盘的两家：**

- **Variational**：交易接口尚未对用户开放，API key 不能自助申请（官方文档：「contact
  hello@variational.io」），而且是 RFQ 成交。没有可用的官方接口。
- **Ourbit**：公开文档只覆盖现货；合约私有接口只存在于官方 Postman 集合与 JS 示例里，
  二者互相矛盾（持仓模式路径、计划单路径），指向已失效的域名，状态枚举与 reduce-only
  编码都没有文档。按「签名与语义必须来自官方文档」的原则，不实现。

各家实现要点：

- **Hyperliquid**：按官方签名规则（MessagePack 动作哈希 + EIP-712）用 `k256` 签名，单测对照了
  官方 Rust SDK 公布的主网签名向量。数量按 `szDecimals` 向下取整，价格按 5 位有效数字 / tick
  向有利方向取整；成交与手续费来自 `userFillsByTime`，历史触及 10,000 条上限时拒绝下结论。
  HIP-3 子交易所资产号为 `100000 + dex 序号 × 10000 + 序号`，别名（`GOLD→XAU` 等）与行情连接器
  一致；`fee_per_side` 按部署者费率倍数放大，只会高估不会低估。
- **Lighter**：签名交给官方 `elliottech/lighter-go` v1.0.10 的 `lighter-signer-linux-amd64.so`，
  加载前校验 SHA-256（`1022a277…be392`，与 GitHub release 资产摘要一致），不自己实现签名。
  只支持 Linux x86_64。nonce 从 `nextNonce` 取并先落盘；盘口端点没有快照时间戳，
  价格保护的新鲜度只能保证「发单前 2 秒内拉取」。手续费按每笔成交的实际费率计算。
  Robinhood Chain 部署（`lighter-rh`）签名链 ID 为 466324（Lighter RH 官方 API 文档）；同一
  账户序号 + API key 序号不能同时用于两个部署（签名库按这一对登记客户端）。
- **Arcus**：下单与撤单都是异步的（通常回 `202 ACK`），下单后按 `orderId` 回查到终态，拿不到
  `orderId`（超时、重启）时按客户订单号翻订单历史；刚受理的订单查 404 是「还看不到」，不当成没提交。
  Arcus 的 `clientId` 只在活跃订单间唯一，结束后可复用，所以幂等完全靠意图日志。IOC 零成交时
  交易所记为 `REJECTED` + `IOC_CANCELED`，这里按「撤单、零成交」处理，不当成拒单。开仓前把
  该市场设成所选保证金模式 + 整数杠杆并读回（改杠杆接口权重 125，先读、不一致才改）。价格按所在价格段的
  tick 取整，签名里的整数一律按顶层 `tickSize` 换算，不整除就拒绝签名。开启下单时，连接阶段会
  按一个从没用过的客户订单号撤一次单：签名不对交易所回 401，对了回 `ORDER_NOT_FOUND` ——
  这是唯一一个在构造阶段发出的写请求，不改变任何状态。手续费来自该订单的逐笔成交。
- **CEX 与 Aster**：共用 `live_common`（意图日志、数量与价格取整、订单号映射）。合约规格每单
  现拉；张数制场所按面值换算，reduce-only 数量必须恰好落在步长上。手续费来自该订单的逐笔成交，
  非 USDT 计费、成交量加总与订单成交量不符、同一成交重复出现都会拒绝下结论。
- **拒单与未知的分界**（决定第二腿被拒时第一腿会不会回滚）：只有文档明确的业务拒绝才落终态 `Rejected`，系统繁忙、
  超时、限频一律按结果未知处理（保留意图、不重发、交给对账）。OKX 单笔下单被拒时订单级结论在 `data[0].sCode`
  （信封 `code` 是 `1`），表里只收参数 / 金额 / 价格 / 保证金 / 张数类（51008、51121 等），50011 / 50013 /
  50026 / 50004 不在其内；MEXC 只收 2005 / 2011 / 2015 / 2028 / 2070，500 / 501 / 510 / 513 / 3016 与 HTTP 429 / 5xx
  按未知；Bitget 的 40010 / 45001 / 40725 / 40015 / 40200 / 12004 按未知。MEXC 的限价与最优价偏离不超过 4.9%
  （交易所 5% 硬拒，2070），所以 `ARB_*_SLIPPAGE` 配到 0.05 也不会被拒。OKX 未结订单按 100 条一页翻页，
  撤单要用单笔订单查询确认「已不活跃」才算成功；OKX 对账同时读取逐仓与全仓持仓，订单 `tdMode` 跟随台账模式。
  这些分类来自官方文档，**没有一笔是用真实账户的拒单验证过的**：首次上线请先用最小金额。

### 看板交易（`arb-web`）

看板上的下单、平仓与规则执行调用的是 `arb_exec::desk`，和 `arb-paper` / `arb-live` 是同一份
流程：扫描 → 规则与强平校验 → 深度体检 → 闸门 → 双腿执行与回滚 → 对账。

```bash
# 纸面：只要令牌
ARB_WEB_TOKEN=$(openssl rand -hex 24) ./target/release/arb-web

# 实盘只读：连接账户、对账、出计划，不签名、不发单
ARB_WEB_TOKEN=... ARB_WEB_LIVE=readonly ./target/release/arb-web

# 实盘下单
ARB_WEB_TOKEN=... ARB_WEB_LIVE=trade ARB_WEB_MARKET_SLIPPAGE=0.003 ./target/release/arb-web
```

页面右上角「令牌」面板里填同一个值，并在那里选**交易模式（纸面 / 实盘）**。模式只选这一次：
策略页的下单与持仓页的台账、平仓、规则都按它，不再各自切换；选择记在本浏览器里，顶栏的徽章和
「令牌」按钮随时显示当前模式。选了实盘而这对腿不在实盘场所里时，下单区只说明原因，不会悄悄
换成纸面。

流程：「策略」页选一对腿 →「预览下单计划」（服务端按当前盘口核价、过闸门，不下单）→ 纸面直接
开仓；实盘手输合约名确认后下单。「持仓」页可以平仓（实盘要手输仓位 id）、重试没走完的退出、
手动执行一轮规则；实盘还能查看各家真实持仓与对账结果，停在页面上时每 60 秒自动刷新。

策略表单的「含资金费止盈」与「自动追加逐仓保证金」默认关闭，后者同时填写触发百分比和累计 USDT 上限。
参数修改会使旧预览失效；成功建立双腿仓位后，只有显式点「再开一笔」才清除旧结果并允许重新预览。
失败或结果未知不能靠修改参数、刷新列表、切换页面或模式解除提交锁，应先核对台账与对账，不重发。

每张仍为 `Open` 且双腿完整的持仓卡直接展示「持仓保护与自动平仓」：费差自动平仓、爆仓保护、数量失衡平仓、
基差收敛平仓、净收益止盈和自动追加保证金都可随时开关、调整阈值，点「保存规则」后生效，无需重新下单。
保存时**整套替换**，关闭项明确发送 `off`；「撤销修改」恢复当前已保存设置。
纸面需要令牌；实盘只读可查看、不能修改。草稿跨持仓列表刷新保留，纸面 / 实盘互相隔离。
生效规则保存在服务端台账，重启后仍保留；关闭规则时，本浏览器另记住这笔仓位上次成功保存的自定义阈值（含补款上限），
再次开启不必重填。阈值记忆按仓位与交易模式隔离，且不会自动启用规则；换浏览器时关闭项显示默认阈值。
若新规则按当前行情立即满足触发条件，接口返回 `409 would_trigger`，界面要求勾选风险确认后再保存；
补款 / 减仓与止盈 / 基差平仓同时满足时，确认会一并列出平仓候选，不因缺退出盘口而只提示补款 / 减仓。
改动草稿会清除该确认。`force` 只确认立即触发，不绕过数值范围、配对参数、额度和仓位状态校验。
保存不在 HTTP 请求里执行交易，但后台下一轮可能平仓、减仓或补款。

**两种策略**：策略页顶部切换「资金费套利 / 价差套利」。

- **资金费套利**：按费率定方向（低费率做多、高费率做空），赚费差；入场基差逆风超过门槛的配对不能下单。
- **价差套利**：按价格定方向（便宜的做多、贵的做空），赚两边价格收敛的那段价差；持有期间照常收付资金费
  （方向与资金费可能相反，计划卡片会给出每天的资金费，并在它会吃掉价差收益时警告）。退出靠「基差收敛平仓」
  规则（默认 0.1%）。**「机会」页的价差榜只收批量行情给了买一卖一的场所（CEX 与 Aster）**；策略页的价差视角
  覆盖所有场所：DEX（Hyperliquid 含 HIP-3、Lighter、Arcus）先按「买一 = 卖一 = 标记价」估算（标为上界），
  预览与下单时现拉两边盘口，按扫描器同一套公式重新算可成交价差；再按这笔名义吃完深度后的两腿均价核一遍，
  扣掉平仓穿价与往返手续费后不为正就拒绝下单；设了收敛目标时按「收敛到目标就平」算（计划卡与预览给出收敛到
  目标的净收益和保本目标）。两腿必须落在同一个合约身份里（同名不同资产会被拆成两个簇）。
  命令行等价：`arb-paper <合约> --long <场所> --short <场所> --view spread --basis-exit 0.1`
  （实盘 `arb-live open … --view spread --basis-exit 0.1`）。

**费差反转的防护**（资金费套利，三层）：

1. **开仓前看稳定性**：回看两腿最近的逐小时资金费（Hyperliquid 系 `fundingHistory`、Lighter 系 `fundings`、
   Arcus `/v1/fundingRates`，按整点对齐、缓存 10 分钟），过去 24 小时费差（空腿 − 多腿）均值年化为正、至少 60%
   的小时为正、最近 6 小时均值没有反转，三项都过才能下单，否则拒绝并写明原因；历史不够判断也拒绝。有场所没接入
   历史（CEX）时不核对。`ARB_REQUIRE_STABLE_FUNDING=off` 关闭。预览、下单、后台预检和 `arb-paper` 是同一道检查。
   Lighter 的历史只有 0.0001% 的精度，够判断符号与量级，不够看细节。
2. **持仓后按平均判断**：「费差自动平仓」看最近 6 小时的平均而不是一个读数，一次瞬时波动不会平仓，真正的反转
   几小时内就会拉低均值。策略页下单表单里这条规则**默认打开**（5%）；门槛不低于当前费差时开仓被拒（会立刻被平）。
3. **平仓前核对成本**：均值转负就直接平（继续持有只会白付）；仍为正但低于门槛时，现拉盘口算平仓要多付多少
   （手续费加穿价），超过「按门槛水平算一周的收益」就继续持有，盘口拉不到也不盲平。

**运维与生产化**

- **告警通知**（Telegram，可选，`ARB_ALERT_TELEGRAM_TOKEN` + `ARB_ALERT_TELEGRAM_CHAT`）：规则平仓 / 失败、外部平仓被识别、
  裸敞口、对账连续 3 轮不一致（恢复时再发一条）、盈亏核算完成、实盘手动开平仓、服务启动。同类消息 30 分钟内只发一次，
  全局每分钟最多 6 条；发送在后台任务里、带超时，失败只记日志；消息里不含地址 / 账户号 / 密钥，发送前还会把 32 位以上
  的十六进制串抹掉。没配就什么都不发。
- **Telegram 机器人菜单**（同一组密钥，`ARB_TELEGRAM_COMMANDS=off` 可关）：`/menu` 弹出按钮菜单，也注册到 Telegram 输入框的「/」
  菜单里：`/status` 系统状态、`/positions` 持仓与盈亏（价格、手续费、已收资金费、合计）、`/daily` 今日已实现盈亏、
  `/balance` 各账户可用保证金、`/top` 当前最优资金费机会、`/mute [分钟]` 静音告警（最长 24 小时）、`/pause` `/resume`
  暂停 / 恢复网页里的实盘开新仓。**只有管理员的私聊能用**（用户 ID 必须等于管理员 ID，群里、别人发的一律静默忽略）；
  **没有下单和平仓命令**，平仓请在面板里输仓位号确认；暂停开仓不影响平仓、规则、对账，**暂停状态落盘**
  （`<台账>.pause`），重启后仍然暂停（文件读不懂时按已暂停处理）。长轮询
  `getUpdates`，启动时丢弃停机期间积压的消息；同一个 token 同时只能有一个进程在轮询。
  只读查询最多并发 2 条、各自取数超时 20 秒，避免慢账户接口让后续暂停 / 恢复命令排队；控制命令仍按接收顺序执行。
  `/positions` 与 `/top` 显示行情快照的 UTC 时间和年龄，过期有提示。行情默认每 60 秒刷新，资金费流水缓存最长
  5 分钟（交易所结算也可能延迟）；这不是逐秒账户盈亏。超时明确提示未知，不返回伪造的 0，并记录查询耗时便于排查。
- **`/healthz`**：给 pm2 / 外部监控用，不需要令牌，只含布尔值、时间和计数。快照过期（扫描卡住）或实盘规则轮停了
  （超过三个周期没跑）返回 **503**；带上规则轮上次多久前、对账是否干净、连续不一致轮数、告警是否启用。
- **开仓前核对可用保证金**（实盘）：盘口检查之后、下单之前，读两个账户的可用保证金（Arcus `freeCollateral`、Hyperliquid
  账户价值减已占用保证金、Lighter `available_balance`），不够这笔要占的（名义 ÷ 杠杆 × 1.1）就拒绝 —— 关掉单笔上限后，
  「盘口够、账户不够」会让第一条腿成交、第二条失败、被迫付一次回滚。查不到的场所只警告、不拦。
- **当日已实现盈亏自动取自台账**：实盘开仓表单里这一项留空时，服务端用台账里今天（UTC）结束的仓位算（价格 − 手续费 +
  资金费），每日亏损闸门（`ARB_MAX_DAILY_LOSS_USDT`）因此有了真实数据；台账里有今天结束、但盈亏没有记录的仓位时算不出来，
  仍要手填 —— 不知道的不按 0 算。只算看板台账里的平仓，交易所里手动交易不在内。早于逐笔记账上线、当时没记盈亏的已平仓仓位，
  后台会按成交记录补上。
- **响应压缩**：所有文本响应（JSON / JS / CSS）支持 gzip（`/api/scan` 一次 13 MB，压缩后小一个数量级）。
- **日志**：「字段不可用的合约已跳过」、场所取数失败、对账不一致都只在**变化时** WARN（持续不变只记 DEBUG），
  场所恢复、对账恢复各记一条 INFO；pm2 的日志轮转（`pm2 install pm2-logrotate`）请自己装，装它会影响所有 pm2 进程。
- **优雅停机**：收到 SIGINT / SIGTERM 后先置「停机中」（新的下单 / 平仓 / 规则轮一律不再开始，返回 503），
  再让进行中的请求跑完，然后**等纸面与实盘交易台上的操作做完并一直持有两把锁**，最后发一条告警退出。整个排空
  有时限（`ARB_SHUTDOWN_GRACE_SEC`，默认 120、上限 300），超时照样退出并告警「某张交易台上还有没做完的操作」；
  排空期间再来一个信号立即退出。pm2 的 `kill_timeout` 由 `ecosystem.config.js` 按「时限 + 30 秒」推出
  （pm2 默认 1.6 秒就 SIGKILL，会把两条腿之间的下单劈开），systemd 见 `deploy/arb-web.service`。
  下单 / 平仓 / 一轮规则都跑在**独立任务**里：浏览器关页面、反向代理超时、`curl` 被 Ctrl-C 都不会把
  一次开仓劈成「第一腿成交、第二腿没发」（实测：不这样做，客户端 0.3 秒断开就会留下只有一条腿的仓位）。
- **崩溃一致性**：台账末尾写到一半的记录（断电 / OOM）在重启时挪进 `<台账>.torn` 留证并从台账截掉，不再封口成
  一条永久解析不了的坏行（那会让对账拒绝一切开仓与规则）；读者只读已经写完整的行，不会把另一个任务正在追加的半行
  当成坏行。启动时先把台账里停在 `Pending` 的订单按各券商的订单日志核实成终态（券商从没收到的记 `Rejected`；
  有成交而台账没记的会告警，对账会如实报持仓不符），否则它们会成为永远消不掉的「本地有挂单、交易所没有」。
  从没成交过的 `Opening` 仓位记为 `Unwound`，不再记成一笔盈亏为 0 的已平仓。减仓订单号在**发单前**先落盘推进
  （此前减仓做到一半失败，下一轮会复用同一个订单号，券商拒绝重发，爆仓保护就此失效）。
- **没走完的退出**：对账不干净时仍然重试 `Closing` / `Unwinding` 的退出（reduce-only，补的是裸腿），规则与开仓
  没走完的 `Opening` 不动（那时第二腿可能其实成交了）。每笔仓位的退出重试按 30 秒、1 分、2 分……封顶 30 分钟退避，
  不放弃也不再每轮刷一遍接口。第二腿结果不明时仓位保持 `Opening` 并在备注里写明原因，**不自动回滚**。
- **熔断与暂停**：连续 3 笔开仓以回滚收场（`Unwound`）就自动暂停开新仓并告警；平仓、规则、对账不受影响。手动
  `/resume` 时记下时刻，之后只数新的失败。
- **行情取数的限频保护**：所有连接器共用同一处 `http::get_json`。429 / 418 按 `Retry-After`（没有则
  Lighter RH 120 秒、Lighter 与 Aster 60 秒、其余 30 秒，上限 5 分钟）让这家场所**冷却**，期间扫描、预检、盘口、K 线
  都不再发请求，直接报错说明还剩多久；连接失败、超时、5xx 只重试一次（200 ~ 500 毫秒抖动），Lighter RH 与 429
  从不重试。每家场所一轮扫描有总时限（HTTP 超时的 2 倍），一家卡住不再把整轮拖成各请求超时之和。扫描任务 panic
  只作废那一轮（此前会让后台刷新永久停掉、快照冻结而进程仍然在线）。
- **Binance 已下架合约**：`premiumIndex` 会继续列出 `SETTLING` 的已下架合约（实测 134 个，费率停在 0、结算时刻
  还是将来），按 `exchangeInfo.status = TRADING` 过滤（缓存 10 分钟，取不到沿用上一份）。
- **`/metrics`**：Prometheus 文本格式，不要令牌（只含计数、时间和布尔值，标签取值有限）：快照年龄、各场所上一轮
  是否成功 / 耗时 / 读数条数 / 限频冷却剩余、实盘规则轮是否停摆 / 上一轮多久前 / 对账是否干净 / 连续不一致轮数 /
  是否暂停开仓、台账里各状态的仓位数，以及下单 / 平仓 / 规则操作的成败次数、令牌校验失败次数、后台任务 panic 次数、
  是否正在停机、常驻内存。告警建议：`arb_live_rules_stalled == 1`、`arb_live_reconciliation_clean == 0` 持续数分钟、
  `arb_snapshot_age_seconds > 3 × 扫描间隔`、`arb_venue_up == 0` 持续、`arb_live_opens_paused == 1`、`arb_live_connected == 0`（实盘账户暂时连不上）。
- **安全响应头与令牌失败**：所有响应带 `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、
  `Referrer-Policy: no-referrer`、`Content-Security-Policy: frame-ancestors 'none'`、`Cache-Control: no-store`。令牌校验失败
  计数并在累计次数为 2 的幂时 WARN（不记提供的内容）。

**手动平仓的自动识别**：你在交易所手动把仓位平掉后，后台规则轮（每 60 秒，`arb-live watch` 同理）对账会发现
「台账有仓、交易所没有」。**两条腿都归零、并且连续两次对账（间隔 ≥ 60 秒）都如此**，就在台账里把这笔记成已平仓，
备注写明是外部平仓、已实现盈亏未知（看板没有这次成交记录）和开仓以来的资金费。整个过程**只识别、不下单**。
以下情况一律不处理、只在持仓页提示：只平了一条腿（裸敞口，看板不会自动平剩下的腿）、数量与台账不符、
这些场所有没核对完的查询 / 挂单或台账之外的持仓。识别完会重新对账，不会因为这笔自己的不一致再让其它规则多跳过一轮。
对账不干净时，每一轮都会在日志里留下每处不一致的类型、场所与详情。

**手动平仓的实际盈亏**：被识别为外部平仓的仓位，看板事后按交易所自己的成交记录核算实际盈亏，并写进台账、显示在持仓页
「最近结束」的「已实现盈亏」列（悬停看明细）：价格盈亏（开仓价取台账、平仓价取成交）− 手续费（开仓 + 平仓，每笔只计一次）+
持仓期间交易所实际结算的资金费。成交记录来自 Arcus `/v1/fills`、Hyperliquid `userFillsByTime`、Lighter `trades`；
**只在数量逐腿严格对得上时才记**（开仓方向、平仓方向的成交总量都要等于台账那条腿的数量，误差 0.1%，且没有混进反向开仓
或别的开仓 / 平仓）—— 成交记录是按账户和合约查的，别的交易也在里面，对不上就不猜，每 5 分钟重试一次、最多 6 次，
仍不行就把原因记进台账，页面显示「核不出」。全程只读交易所。看板自己平仓的仓位同样记录资金费。

**资金费的口径与事后核对**：资金费一律按**开仓时的两条腿**、**[开仓, 平仓] 时间窗口**取交易所结算流水
（平仓重试中只剩一条腿、外部平仓时腿已清空，也从台账历史里找回两条腿；之后同一合约上新开的仓位的结算不会被算进来）。
任一条腿查不到就记「未知」，不拿一条腿冒充合计。平仓那一刻两家的流水可能一前一后出现，所以平仓 10 分钟后看板后台
按同一窗口再查一次：一致只记下核对时刻（`funding_checked_at`），不一致就**追加**一条更正记录（旧行不动，重放取最新）、
备注写明旧值→新值与修正后的净额，并推送 Telegram。每轮最多核 2 笔，避免挤占 Lighter RH 的限频额度。

**手动对账**：`crates/exec/tests/pnl_audit.rs` 用关着下单开关的连接，按交易所成交记录与资金费流水**独立**重算每笔已平仓
仓位的价格盈亏、手续费、资金费，逐项与台账对比；另一个用例在台账**副本**上演练资金费更正。都是只读、默认忽略：

```bash
cd crates/exec
ARB_AUDIT_LEDGER=/path/to/arb-live-ledger.jsonl ARB_AUDIT_ENV=/path/to/.env \
  cargo test -p arb-exec --test pnl_audit -- --ignored --nocapture
```

运行中的看板对订单意图日志持独占锁，工具会先把日志复制到临时目录再连接；输出只有仓位号、合约、场所与金额。

**只显示能下单的（后台预检）**：策略表是按扫描快照排的，「能不能下」要现拉盘口走一遍闸门才知道。
策略页开着时，看板后台按右边表单里的**单腿名义、杠杆、平仓规则**和右上角的**纸面 / 实盘**，对当前这对
场所**所有**看上去能做的合约调用与「预览」同一个 `desk::prepare`；表格和 Top 卡片默认只列通过的
（「只显示能下单的」，取消勾选可以看全部和每一行不能下的原因，悬停徽标看原因）。

- **打开就有结论**：最近用过的 4 组参数记在 `ARB_PRECHECK_STATE`（默认 `arb-precheck-watches.json`）里，
  网页关着、看板重启后也按它们在后台慢一些地继续查（通过的 4 分钟、其余 10 分钟一轮）；页面也记住上次的
  场所、金额、杠杆，再打开时正好对上。第一次用的新组合要等一轮（先查选中的和排名靠前的）。
- 有人在看时：选中的那一行 30 秒重查、通过的 90 秒重查、不过的 2 ~ 5 分钟重查；还没查过的排在重查前面。
  通过的结论超过 6 分钟没重查成就不再算能下单。重查碰到限频、没查成时保留上一次的结论。
- 扫描快照已经能判死的不拉盘口：至少一条腿触及 OI 上限；价差视角两腿都有买一卖一、可成交价差不为正
  或扣成本不划算。平仓规则（基差收敛目标、爆仓保护）在展示时拿结论里的强平距离现比，改规则不重新拉盘口。
- 账户级的关单独说明、整张表不列：持仓数已到上限（5 笔）；实盘最近一次对账不干净（预览、刷新实盘账户
  都会对账）；实盘模式下只在已连接实盘的场所之间选。实盘只读（`ARB_WEB_LIVE=readonly`）时照常列出，
  并提示「开启下单后能下的，现在只能预览」。
- 预检自己的盘口请求按场所限速（`lighter-rh` 5 秒、Lighter 2 秒、Aster / Arcus 1 秒、Hyperliquid 系
  0.5 秒、其余 0.3 秒一次，碰到 429 冷却 2 分钟），几分钟没人看就停，最多同时关注 3 组参数。大表
  （CEX 对两三百行）第一轮要几分钟，能下单的会陆续出现。
- 当日亏损只有下单时才知道；DEX 之间的薄价差几十秒就会变。下单前的预览仍是准的那一个。
- 盘口厚度按深度判断：限价（最优价 ± 0.2%）以内要吃得满、预估滑点不超过 0.2%。以前还有一条「单腿名义
  不超过第一档的 2 倍」，第一档常常只挂一笔小单、每秒都在变，连 BTC 都会被拦、能下单的列表来回闪，已去掉。

**实盘持仓的已收资金费**：持仓页按交易所的结算流水显示每条腿开仓以来实际收付的资金费（正 = 收到）、结算次数与
「含资金费合计」。已接入 Hyperliquid（含 HIP-3，`userFunding`）、Lighter（含 RH，`positionFunding`，需鉴权）与
Arcus（`/v1/funding`）；其它场所显示「未接入」，不拿 0 冒充。看板后台每 5 分钟为实盘持仓刷新一次并缓存，打开
页面就是现成的；止盈决策另行现查。缓存按完整开仓时间区分，同一秒内平仓重开也不会继承上一笔的缓存。
流水按（账户, 合约）记：同一账户在同一合约上还有别的仓位时也算在内。纸面仓位不结算资金费，
只显示按当前费率的每日估算。

**交易所账户识别**：实盘场所默认按 `.env` 里的凭据自动识别（`ARB_LIVE_VENUES` 留空或 `auto`）。
没开实盘时，选实盘模式后「持仓」页列出每家交易所的凭据状态（已识别 / 没填全 / 格式不对 / 未配置）、
开启实盘时会连接哪几家、下一步怎么做；开着实盘时附在「实盘账户」卡片里。页面上只有变量名，
不显示任何密钥；识别不联网，读的是看板启动时的环境，改了 `.env` 要重启看板。

安全边界（都在服务端校验，不只靠页面）：

- **令牌**：所有写接口、实盘台账与实盘账户状态都要 `Authorization: Bearer <ARB_WEB_TOKEN>`。
  没配令牌时交易接口全部 403；开实盘却没配令牌，看板拒绝启动。请求体只收 JSON，跨站表单
  伪造不了请求。监听在非回环地址时令牌走明文，请在前面加 TLS 反向代理。
- **实盘默认关闭**。`trade` 模式必须给 `ARB_WEB_MARKET_SLIPPAGE`（与 `--market-slippage`
  同一个校验）。连接失败时看板直接启动失败，不悄悄退回只读。
- **实盘开仓不用缓存快照**：先对账（必须干净），再对实盘场所现扫一轮；杠杆必须是整数，
  超过两腿上限直接拒绝；当日已实现盈亏必填。纸面开仓用缓存快照，快照过期时拒绝。
- **二次确认**：实盘开仓的 `confirm` 必须等于合约 base，实盘平仓的 `confirm` 必须等于仓位 id。
- **不排队、不重试**：同一张交易台上已有操作（或一轮规则）在跑时返回 409。下单出错时页面
  锁住按钮，提示以台账与对账为准，不会自动重发。
- **实盘规则由看板执行**：各家券商持有订单意图日志的独占锁，看板连着实盘时 `arb-live`
  连不上同一批账户，所以 `trade` 模式下看板后台每 `ARB_WEB_LIVE_WATCH_SEC` 秒跑一轮规则
  （对账不干净时跳过自动动作）。要改用命令行执行，先停掉看板的实盘。
- **纸面规则默认不在看板里跑**（`ARB_WEB_PAPER_WATCH_SEC=0`）。纸面台账没有锁，看板和
  `arb-paper --watch` 同时执行规则可能把同一笔仓位平两次，二选一。
- 看板后台扫描与实盘共用出口 IP：`lighter-rh` 限频很紧，实盘连它时建议把它排除在 `ARB_VENUES` 外。

### 纸面与实盘的差别

`PaperBroker` 用**真实盘口**逐档吃单算成交价与手续费（含逐合约的真实费率），不连接私有接口。
重启后它按台账重建各场所的纸面净持仓，所以 `arb-paper --watch` 能平掉之前开的仓。

## 已知边界

- **实盘不支持 Ourbit、Variational**（原因见「实盘执行」）。当日已实现盈亏需要操作者提供。
- **同名不同资产的判定基于参考价（5% 容差）。** 对股票 / Pre-IPO / 商品类永续
  （Lighter 与 Variational 都上了这类合约）只能挡住价格量纲明显不同的情况；
  这些市场的跨场所身份判定需要专门处理，不能只看 ticker。
- **排名里的成本不含多档滑点。** 一档穿价来自批量行情；多档滑点只在 `arb-paper`
  下单前对候选合约计算。Lighter 与 Variational 没有公开 K 线，收敛时间测不到时
  回落到配置的持有期，并标记 `hold_measured = false`。
- **计价资产用报价单位，不是结算资产。** Variational 与 Lighter 的抵押资产是 USDC，
  但合约以美元计价、两条腿之间没有换汇动作，所以都记为 USDT。跨报价单位的配对会被
  打上 `quote_mismatch` 标记（换汇成本**没有**计入手续费模型）。
- 连接器只读**公共**行情；账户数据只在 `arb-live` 的券商里读取。
- **扫描榜的模型强平距离只覆盖公开维持保证金率的场所**（Hyperliquid 系、Lighter 系），且只描述逐仓最低风险档；
  全仓持仓不使用这个模型，只读取交易所报告的有效强平价；缺数据就无法执行爆仓保护。
- HIP-3 只接了 `xyz` 与 `io` 两个子交易所；其余子交易所多数重复上市同一批股票。

## 跨场所价差监控与自动交易

看板「RH 价差」页。两家都在 Robinhood Chain、都用 USDG 保证金，有 37 个同名合约（美股、指数、商品、加密币），
价格偶尔偏离。监控与提醒本身不下单、不连账户；下单只有两种途径：点一行跳到策略页手动预览确认，或在面板上**显式开启**自动交易。

- **行情**：两家的 WebSocket（Lighter RH `order_book/{id}` 增量 + nonce 连续性校验，断档自动重订阅；
  Arcus `l2Orderbook` 25 档完整快照），实测合计约 240 KB/s。不走 REST 轮询：Lighter RH 按 IP 限频极紧，轮询会挤占实盘下单额度。
  断线指数退避重连（1 秒起、封顶 60 秒），断线期间盘口作废；Arcus 盘口 15 秒没更新就不计算。
- **每秒计算**两个方向（多 Arcus 空 RH / 多 RH 空 Arcus）：按估算名义（默认 2000 USDT）吃完两边深度的均价算**可成交价差**，
  再扣**立即平仓穿价**与**往返手续费**（Arcus 基础档 0.0225% × 开平两次；Lighter RH 0；Lighter 没报费率时按 Arcus 费率保守估），
  得到「收敛到 0 净收益」。
- **正常基差**：每个合约每分钟落一行中间价基差的中位数到 `rh-spread/rh-spread-YYYYMMDD.jsonl`（保留 14 天，`ARB_RH_SPREAD_DIR` 可改），
  按**时段**（美股盘中 / 盘后 / 周末，以 Arcus `isOutsideRth` 为准，拿不到时按纽约时间推算；加密币全天）统计过去 7 天的中位数、p10/p90、MAD。
  同一时段攒够 120 分钟才给。股票类合约休市时常有**系统性**偏差（实测 2026-10-07 美股盘后 Arcus 普遍比 RH 便宜 0.1%~0.15%），
  所以提醒看「**回到正常水平**净收益」= 收敛到 0 净收益 − 正常基差里收不回来的那部分，而不是「收敛到 0」。
- **提醒**：回到正常水平净收益 ≥ 门槛（默认 0.05%）、且连续保持 10 秒，推送 Telegram；同一合约同一方向 30 分钟一条，受全局告警限频约束。
  正常水平还没攒够时**不提醒**。
- 接口 `GET /api/rh-spread`（不要令牌，不含账户信息）。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `ARB_RH_SPREAD` | 开 | `off` 关闭监控 |
| `ARB_RH_SPREAD_SIZE` | `2000` | 估算用的单笔名义（USDT，100 ~ 100000） |
| `ARB_RH_SPREAD_ALERT_PCT` | `0.05` | 提醒门槛：回到正常水平的预估净收益（%，0.001 ~ 5） |
| `ARB_RH_SPREAD_EQUITIES_ONLY` | 关 | `on` 只看股票、指数、商品，不看加密币 |
| `ARB_RH_SPREAD_DIR` | `rh-spread` | 分钟历史目录（相对工作目录）；自动交易设置也存在这里（`auto.json`） |
| `ARB_RH_SPREAD_PAIRS` | 见下 | 监控哪几组，`场所A:场所B` 逗号分隔；支持 `arcus`、`lighter-rh`、`hyperliquid`、`hyperliquid-xyz`、`hyperliquid-io` |
| `ARB_ENTROPY_SELF_REBATE` | `0` | Entropy（`hyperliquid-io` 的部署方）自返佣比例，小数：Tier 4 = `2`（200%） |

### 多组监控

默认监控 5 组：`arcus:lighter-rh`、`hyperliquid-xyz:lighter-rh`、`arcus:hyperliquid-xyz`、`hyperliquid-io:lighter-rh`、`arcus:hyperliquid-io`。
每家只连一条行情 WebSocket，几组共用（Hyperliquid 用 `l2Book` 订阅，每侧 20 档完整快照，实测约 5 秒一次，15 秒没更新就不算数）。

- **基差口径**：每组 `(左 − 右) / 均值`，方向 `long_a` = 多左空右。最早那组 `arcus:lighter-rh` 与原来同号，
  历史文件仍是 `rh-spread-YYYYMMDD.jsonl`，已攒的历史照常使用；其它组写 `spread-<左>-<右>-YYYYMMDD.jsonl`，从零开始攒。
- **同名 ≠ 同一资产**：有一边是 Hyperliquid 的组，两边都必须落在扫描器的**同一个身份簇**里（价格分簇，被可信度筛查排除的读数不算），
  所以要等首轮扫描完成才开始订阅；股票 QNT 与币 QNT 这类同名不同资产不会配成一对。
- **手续费（单边，按基础档上限）**：Arcus 0.0225%、Lighter RH 0、Hyperliquid 主 dex 0.045%；
  HIP-3（xyz / io）= 0.045% × deployer 倍数（`scale < 1 ? 1 + scale : 2 × scale`，实测 ×2），开着 growth mode 的合约再 ×0.1（逐合约读 `meta`）。
  `hyperliquid-io` 还按 `ARB_ENTROPY_SELF_REBATE` 扣掉 Entropy 返佣：官方规则按 Entropy 那一半份额返，净费率 = 费率 × (1 − 返佣 / 2)，
  **最低 0、不算成负的**，且只在倍数为 1 时适用（文档写明的五五分成）。见 https://docs.entropy.io/about-entropy/referrals 。
  这套费率同样用于扫描器与下单前的价差核算（`taker_fee`）；**台账记的是交易所实际扣的手续费**，返佣到账要自己在 Entropy 领取，不进台账。
- **自动交易目前只做 `arcus:lighter-rh`**。其它组只监控与提醒：先攒够正常基差的历史、并用第一笔真实成交核对过实际扣费，再开放。

### 自动交易（默认关闭）

在「RH 价差」页的「自动交易」卡片里设置并开启（需要令牌）。开启后每秒检查一次：某个合约某个方向的
「回到正常净收益」≥ 你设的门槛、且**可成交价差与收敛到 0 净收益都为正**、连续保持你设的秒数，就自动下一笔价差单：

- **方向**用监控选出的方向；**退出规则**：「回到正常基差就平仓」（把同时段正常基差按方向换算成基差收敛目标，
  按盘口核对整笔净收益为正才平）、止盈（USDT，含资金费、按盘口核对）、爆仓保护，至少开一条退出规则才能保存。
- **与手动下单同一条路径**（`run_open`）：对账干净、按你的金额现拉盘口重算深度与净收益（不够就拒）、`ARB_MAX_POSITION_USDT`、
  持仓数上限、当日亏损闸门、Telegram `/pause`、连续失败熔断、开仓通知，一项不少。逐仓。
- 自动交易自己的限制：同一合约已有敞口（不论是否自动开的）不再开；自动仓位同时最多 N 笔、每个 UTC 日最多 M 笔；
  两次开仓至少隔 60 秒；某合约尝试过一次（成功或被拒）冷却 10 分钟；被拒后 15 秒内不再尝试。
- **自动关闭**：执行中断（结果未知，可能留下单腿）立即关闭并推送；连续 2 次以回滚收场关闭；请求不合法 / 只读模式关闭。关闭原因显示在面板上。
- 开启**实盘**要输入 `LIVE` 二次确认；实盘没连上或只读模式时不能开启；实盘断线期间自动暂停，重连后继续。
- 设置与「自动开过哪些仓」存在 `<ARB_RH_SPREAD_DIR>/auto.json`（0600，原子替换），**重启后沿用**（开着就继续开着，启动日志与 Telegram 会提示）。
  文件读不懂时按关闭处理。
- 纸面自动交易：纸面仓位的退出规则要 `ARB_WEB_PAPER_WATCH_SEC` > 0 才会在后台执行，否则只能在持仓页手动「执行一轮规则」。
- 接口：`GET /api/rh-spread/auto`（状态、最近动作）、`POST /api/rh-spread/auto`（整套替换设置），都要令牌。

> 注意：监控表格的净收益按 `ARB_RH_SPREAD_SIZE` 估算；你的单笔比它大时吃得更深、实际更差（下单前按你的金额重算，不够会被拒）。
> 正常基差是统计量，不保证回归；没回归时仓位会一直持有到止盈 / 你手动平仓。建议先用纸面跑一段时间、小金额起步。

**局限**：正常基差是统计量，不保证回归；没有算资金费（持有几小时以内可忽略，持有更久要另看费差）；
不含 Arcus 单笔下单上限、OI 上限与两腿成交时差的风险。这些都是第二阶段「一键开仓」要处理的。

| `POST /api/trade/rules` | 🔑 整套替换持仓规则：`{mode, position_id, force:false}` 加上述全部规则字段；省略 / `off` 关闭。立即触发时返回 `409 {error, would_trigger}`，显式确认后才可用 `force:true` 再提交；累计补款金额保留 |

| `GET /api/trade/live/status` | 🔑 实盘账户：各家真实持仓、账户费率、对账结果 |
| `GET /api/trade/accounts` | 🔑 交易所账户识别：每家凭据齐全 / 没填全 / 格式不对 / 未配置，以及开启实盘时会连接哪几家。只有变量名，不含任何值，不联网 |

🔑 = 需要 `Authorization: Bearer <ARB_WEB_TOKEN>`。

## 开发

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Lighter 原生签名回归显式 `ignore`，避免把未安装签名库误记成通过。安装钉住版本后可以离线运行整个模块：

```bash
ARB_LIGHTER_SIGNER_LIB=/opt/lighter/lighter-signer-linux-amd64.so \
  cargo test --offline -p arb-exec --lib lighter_broker::tests -- --include-ignored
cargo test --offline -p arb-exec --lib arcus_broker::tests
```

前一条使用公开测试私钥、空 HTTP 地址与显式 nonce，不发送交易；缺库或 SHA-256 不符会失败。
后一条只跑本地夹具，不打开已标记 `ignore` 的主网公开账户测试；不要给它加 `--include-ignored`。

前端资源用 `include_str!` 编进二进制，改完 `crates/web/web/` 下的文件需要重新构建。

## 部署

- **pm2**：`ecosystem.config.js`（`kill_timeout` 已按排空时限推出）。改完执行 `pm2 restart arb-web --update-env`、`pm2 save`。
- **systemd**：`deploy/arb-web.service`（沙箱：`ProtectSystem=strict`、只写 `/var/lib/arb-bot`、`NoNewPrivileges`、
  `MemoryMax`；`TimeoutStopSec` 必须大于排空时限）。密钥放 `/etc/arb-bot.env`（0600）。
- **必须备份、不能删**：实盘台账 `arb-live-ledger.jsonl`、每家的订单意图日志 `arb-live-<场所>-orders.jsonl`、暂停状态
  `<台账>.pause`。意图日志是「这个订单号发出去过」的唯一证据，删了它重试会被券商拒绝、或更糟 —— 重发。
- **CI**：`.github/workflows/ci.yml` 跑 `fmt` / `clippy -D warnings` / `test`，主分支再做一次 release 构建。CI 里不配任何
  `ARB_*` 密钥，测试不碰网络与账户。
